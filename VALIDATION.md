# Detection Rule Validation Notes

These XML files are **starter examples**, not guaranteed drop-in rules. Wazuh built-in rule IDs and decoded fields can vary by release and log source.

Before using them:

1. Back up `/var/ossec/etc/rules/local_rules.xml`.
2. Review the Wazuh alerts generated by your actual Windows and Linux test events.
3. Confirm the built-in parent rule IDs and decoded fields in your installed version.
4. Merge rules into `local_rules.xml` carefully; avoid duplicate IDs and malformed group nesting.
5. Validate configuration and restart only according to the official documentation for your installed release.
6. Confirm the rule triggers on the intended lab events and does not trigger on unrelated events.
7. Record the test date, Wazuh version, event sample, expected result, actual result, and false-positive observations.

A frequency/timeframe rule is not necessarily grouped by source IP or username just because its description says so. Confirm the correlation behavior; add appropriate field matching or a supported correlation approach if you need per-source/per-account grouping.

Official docs: https://documentation.wazuh.com/current/user-manual/ruleset/rules/custom.html
